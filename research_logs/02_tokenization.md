# GPT-2 Tokenization

## Objective

Understand how raw sentiment text is converted into numerical input that the custom GPT-2 model can process.

## Why This Step Is Important

GPT-2 cannot directly process text strings. The tokenizer converts text into token IDs, which are mapped to learned embedding vectors inside GPT-2.

Understanding tokenization, padding, sequence length, and attention masking is necessary before creating training batches.

## Tokenizer

The pretrained GPT-2 tokenizer was loaded using:

`GPT2TokenizerFast.from_pretrained("gpt2")`

## Vocabulary

Vocabulary size:

`50,257`

This matches the custom GPT-2 configuration:

`vocab_size = 50257`

Therefore, token IDs generated by the tokenizer are compatible with the custom GPT-2 embedding layer.

## Special Tokens

EOS token:

`<|endoftext|>`

EOS token ID:

`50256`

GPT-2 does not contain a dedicated padding token by default.

For batching, the EOS token will also be used as the padding token:

`pad_token = eos_token`

Padding positions will be distinguished from real tokens using an attention mask.

## Sequence Length Analysis

The token lengths of the 60,614 training samples were analyzed before selecting a maximum sequence length.

Results:

* Minimum: 2 tokens
* Maximum: 65 tokens
* Mean: 12.36 tokens
* Median: 9 tokens
* 90th percentile: 26 tokens
* 95th percentile: 32 tokens
* 99th percentile: 43 tokens

Samples exceeding selected thresholds:

* More than 32 tokens: 2,809 samples (4.63%)
* More than 64 tokens: 1 sample
* More than 128 tokens: 0 samples

## Maximum Sequence Length

The experiments will use:

`max_length = 64`

Only one training sample exceeds 64 tokens.

This provides near-complete dataset coverage while reducing unnecessary memory and computation compared with GPT-2's full 1,024-token context window.

## Dynamic Padding

Training batches will use dynamic padding.

Instead of padding every sentence to 64 tokens, each batch will be padded only to the length of the longest sequence in that batch, up to the maximum length of 64.

This reduces unnecessary computation because the average SST-2 sentence contains only 12.36 tokens.

## Attention Mask

The tokenizer generates an attention mask alongside the token IDs.

Example:

`input_ids = [token, token, token, token, PAD, PAD]`

`attention_mask = [1, 1, 1, 1, 0, 0]`

A value of `1` represents a real token.

A value of `0` represents a padded position.

## Custom GPT-2 Modification

The custom GPT-2 implementation originally supported only causal masking.

The attention implementation was extended to also accept a padding attention mask.

The two masks serve different purposes:

* Causal mask: prevents a token from attending to future tokens.
* Padding mask: prevents the model from attending to padded positions.

This allows the custom GPT-2 implementation to correctly process padded classification batches.

## Custom GPT-2 Batch Verification

After implementing padding-mask support, a padded batch was passed through the custom GPT-2 Small architecture.

The test verified that:

* Input token IDs can be passed to the custom GPT-2 implementation.
* Padding attention masks are accepted by the Transformer blocks.
* The model runs successfully on the GPU.
* The output dimensions are consistent with GPT-2 language modeling.

For an input batch with shape:

`[batch_size, sequence_length]`

the current GPT-2 language-model output has shape:

`[batch_size, sequence_length, vocabulary_size]`

The vocabulary dimension is 50,257 because the model currently predicts vocabulary scores for every token position.

This is expected because the architecture has not yet been converted into a sentiment classifier.

## GPT-2 Architecture Verification

The custom GPT-2 implementation was tested using a padded two-sentence batch on the GPU.

### Forward Pass Results

* Device: CUDA
* Input shape: `[2, 8]`
* Attention-mask shape: `[2, 8]`
* Output shape: `[2, 8, 50257]`
* Transformer blocks: 12
* Embedding dimension: 768
* Vocabulary size: 50,257

The output dimensions are consistent with GPT-2's language-modeling architecture, where the model produces one vocabulary score vector for every input token position.

### Parameter Count Observation

The initial implementation reported:

`163,037,184 parameters`

This was higher than the expected GPT-2 Small parameter count of approximately 124 million.

The difference was caused by using independent parameters for:

* the input token embedding matrix, and
* the output vocabulary projection matrix.

Each matrix contains:

`50,257 × 768 = 38,597,376 parameters`

### Weight Tying

Original GPT-2 shares the token embedding weights with the output vocabulary projection.

The custom implementation was therefore updated using weight tying:

`self.out_head.weight = self.tok_emb.weight`

This removes the duplicated parameter matrix while maintaining the same output behavior.

### Why This Matters

Matching the pretrained GPT-2 architecture before loading pretrained parameters is important because architectural inconsistencies can make weight transfer incorrect or misleading.

The architecture is being verified independently before pretrained weights are introduced.
